# v2 規格 H — 三鑰逃生(闖關化定案,取代事故報告框架)

> 【狀態】**設計中,待動工**(2026-08-04 使用者拍板方向,指定「先寫 spec 再動手」)。
> 【來源】玩家試玩回饋:**「雖然很多提示,但感覺很亂」**;使用者定調:
> 「這是闖關遊戲,縮減 3 個關。玩家是打工仔已經超時加班,想下班 → 老油條員工來阻止 → 打贏回收 →
> 掉落魔法鑰匙(1/3) → 領班出來奪回魔法鑰匙 → 打贏回收 → (2/3) → 老闆出來阻止 → 打贏回收 → (3/3) →
> 湊齊後順利逃生下班。**再也沒有魔法事故報告了,那是舊的想法。**」
> 【關係】**取代規格 E 的北極星**(每局產一份好笑報告)與 `docs/campaign.md`(2026-07-16 闖關決策,未動工——
> 本規格是它的收斂版,差異見 §11)。**規格 G(記錄 3 筆 → 收容終演)原封保留**,降級為「單關勝利條件」。
> 戰鬥系統(brawl-1~3.1 / 道具 / 地板化學 / 疲態 / 終演)**一行不動**——闖關是包在外面的殼。

## 0. 一句話

> **你是超時加班想下班的打工仔。三個同事依序擋在你和大門之間;把他打到失能三次、扔進回收艙,
> 他就掉一把魔法鑰匙。湊齊 3 把,開門下班。**

動詞完全沒變,變的是**你為什麼要做這件事**。

## 1. 為什麼換框架(病因診斷)

玩家說「提示很多但很亂」。**病根不是提示的數量,是目標本身需要被解釋。** 舊框架要玩家吞三層抽象:

| 舊框架的一層 | 玩家要自問 |
|---|---|
| 事故記錄 | 我打人為什麼叫「記錄事故」? |
| 收容封存 | 我為什麼要把同事塞進回收艙? |
| 事故報告 + S~E 等級 | 這個分數在評我什麼?我要刷高它嗎? |

新框架只有一層:**打贏擋路的人 → 拿鑰匙 → 開門下班**。三個名詞全是日常語意,零解釋成本。
而且**「把擋路的同事丟進回收艙」在打工仔框架下天然成立**——比「收容測試」更好笑,也更好懂。

> ⚠ **換框架不會自動治好「很亂」**。文案換皮只解決一半;另一半是 HUD 同時常駐太多層資訊——
> 光教練行就有 **13 條互斥分支**(`v2-hud.js:241-253`),加上標題列、AI 狀態列、橫幅、艙口 LED、
> 滿場浮字。§7 是這個規格真正的另一半藥,**不能只做換皮就收工**。

## 2. 世界留著,任務換掉(這是最省的一刀)

掃描全部文案後的關鍵發現:**場景本身完全不用改**。工業回收中心、回收艙、艙口 LED
(「回收目標已捕捉」/「分類完成:易燃魔法廢棄物」)、地板標語(`WIZARD INTAKE` / `NO MANUAL SORTING`)、
廢料名稱、道具名稱——**這些在「打工仔的工廠」框架下全部成立,一個字都不用動**。

要換的只有**「為什麼打架」那一層**:標題列、教練行、開場、橫幅、終演提示、結算畫面。

| 系統 | 現況 | 新框架 |

| 記錄 3 筆 → 收容指令 → 終演封存(規格 G) | 一局的完整循環 | **原封保留**=**單關**勝利條件 |
| 終演演出(自動抓搬拋 + 特寫 + letterbox) | 一局一次 | 保留,**尾巴接鑰匙掉落**(§5) |
| 疲態 / 立案 beat / 瀕界心跳(flow-2) | — | 保留(`f.fatigue` 由 `roundWins[1-pid]` 導出,語意天然對應「你快撐不住了」) |
| 道具 / 爆桶 / 元素站 / 拉桿 / 地板化學 / lab 場景 / 艙口 LED | — | **全部不動** |

| `applyStage`(危險物升級) | **場內即時**:比分領先就升級 | **改綁關卡**:關 1=普通、關 2=黃色警戒、關 3=全面失控 |

## 3. 關卡狀態機

新增 `v2s.camp = { level: 1, keys: 0, phase: 'fight', deaths: 0 }`,取代「打完一局就 matchOver」的單局模型。

```
boot → menu ─(開始遊戲)→ intro ─→ fight(n) ──記滿3筆──→ order(n) ──打暈+X──→ perform(n) ──→ keydrop(n)
                   ↑                                                          │
                   │                                              ┌───────────┴──────────┐
        (敗北:自己被記滿3筆)                                   keys<3                  keys=3
                   │                                              ↓                       ↓
                retry(n) ←──────────────────────────────  handoff(n+1) → fight(n+1)    escape → clockout
```

| 狀態 | 內容 | 復用什麼 |
|---|---|---|
| `menu` | **主選單**:小人在流水線上循環工作 + 標題 + 開始鈕(§14) | `conveyorBelt()` + `CAM_MENU` + DOM overlay |
| `intro` | 小人離開流水線走向大門 → 老油條擋住 → 台詞(§14.5);只有第 1 關播完整版 | `INTRO_T`/`INTRO_GO` + `CAM_INTRO→CAM_FIGHT` 混合(`v2.js:79-95`) |
| `fight(n)` | 正常戰鬥,目標=記滿 3 筆 | 現況原封(`recordIncident`,`v2-combat.js:236`) |
| `order(n)` | 收容指令(賽末點) | 規格 G 原封(`roundWins[w] >= RECORD_TARGET`) |
| `perform(n)` | 終演:自動抓搬拋 → 封存 | 規格 G 原封(`startPerform`/`finishPerform`) |
| `keydrop(n)` | **鑰匙從回收艙彈出 → 入袋**(§5) | flow-2b 印章卡飛行 |
| `handoff(n+1)` | 下一個 boss 走進場 + 一句台詞 | **`updateAiCall`(`v2-combat.js:862`)整套**——它本來就是「CALL_T 秒後在指定座標放一個新對手進來、比分保留」 |
| `retry(n)` | 「今天不用下班了」→ 重打本關 | `restartMatch` 拆一半(清 `roundWins`,**不清 `camp.keys`**) |
| `escape` | 大門/打卡機亮起 + 指引 | 新(小) |
| `clockout` | 下班結局 | 取代 `drawReport` 那張卡 |

### 三個必須寫進程式碼的分界

1. **`finishPerform` 目前是二分岔**(`v2-combat.js:830-836`):`final` → `finalSeal`→`endMatch`,否則
   → `softReintegrate`(對手復活繼續打)。新流程要改成 **`final` → `keydrop`**,而 `softReintegrate`
   那條路在闖關裡**用不到了**(單關只封存一次)——但別急著刪,`?tune`/加班模式還會用。
2. **`endMatch(pid)` 保留但脫鉤報告**:`v2s.matchOver` 不只給報告用,它還凍結 sim、擋計分、
   擋 pod pulse(`v2.js:198-201`、`v2-combat.js:237,688,751`)。**留著 `matchOver`,只拿掉 `report`**。
3. **敗北定義**:玩家自己被記滿 3 筆 → 對手對你走完終演 → `retry(n)`。
   **建議定案:重打本關,鑰匙保留,不做命數/續關幣。** 單關 1~2 分鐘,全部重來會把
   「快下班了」的張力變成挫折;portal 慣例也是死亡零懲罰。`camp.deaths` 累計當結算笑點。

### ⚠ 命名地雷:不要重用 `v2s.stage`

`v2s.stage` 現在的語意是**「由比分導出的危險等級」**(`applyStage` 被 `recordIncident` 呼叫)。
新設計想要的是**「第幾關」**——因果方向剛好相反。若直接沿用同一個欄位名,
`ring.mjs:30,48` / `finisher.mjs:31,51,53` 這幾條 `stage === 1|3` 的斷言會**用錯誤的理由通過**。

**定案:關卡索引叫 `v2s.camp.level`;`v2s.stage` 維持「危險等級」語意,但改成由 `camp.level` 直接設定
(關 n → stage n),不再由比分推。** 上述斷言一律重寫,不靠它們自己碰巧綠。

## 4. 三個 boss 檔案

`AI_PROFILE`(`v2-state.js:171`)現有旋鈕:`name / punchChance / hesitate / backoffT / grabDelay /
jumpChance / guard / comboDrop`。註解本來就寫著「之後領班/廠長=加列(campaign)」——這條路當初就鋪好了。

| 關 | 對手 | 人設 | 手感目標 | 旋鈕方向 | 場地 |
|---|---|---|---|---|---|
| 1 | **老油條員工** | 混水摸魚、賴著擋路 | 慢半拍;新手能贏 | 貼近現有 `intern`,但 `guard: true`(賴防=人設) | stage 1 普通 |
| 2 | **領班** | 管你、催你回去工作 | 壓迫感來自**場地**不是他本人 | 貼近現有 `senior` | stage 2 黃色警戒 |
| 3 | **老闆** | 最後一道關卡 | 全開,逼你用完前兩關學的東西 | `punchChance`/`jumpChance` 最高、`guard: true`、`comboDrop: 0`、`grabDelay` 最短 | stage 3 全面失控 |

**設計鐵則:三關的勝利條件完全一致**(記滿 3 筆 → 終演封存)。**不給老闆特殊規則**
(不可抓 / 鉤拳免疫 / 三段擊倒)——那是 `campaign.md` 舊版設計,會讓最後一關**要重新教一次玩法**,
正好違背「不要亂」這個目的。老闆的難度來自**旋鈕 + 場地**。

### 實作要點(掃描確認過的)

- `AI_PROFILE` 只有 `name` + 7 個行為旋鈕,**沒有顏色 / 體型 / 血量 / 立繪欄位**;
  顏色是全域 `COLORS[pid]`,名字是**可變陣列** `NAMES[1]`(`applyAiTier` 直接寫)。
  三個 boss=**加三列 + 每列多一個 `nextTier`**(現在 `updateAiCall` 把 `'senior'` 寫死在 `v2-combat.js:866`)。
- **AI 現在完全不碰道具**:`aiMove` 裡沒有任何 `pickupItem`/`useItem`/桶瓶分支;
  也**永遠不會衝刺拳**(`v2.js:301` 只有 `_fleeing` 時才給 AI `running`)。
  → **「領班愛用道具」是新行為,不是加一列旋鈕。建議先不做**(§12 加分項)。
- `v2-combat.js:935` 已有註解「counter 留給領班/廠長檔」——反擊拳目前 player-only,是老闆的天然升級點。
- **實習生逃跑(`_fleeing`)在闖關裡退役**:boss 要被你收容才會掉鑰匙,不能讓他跑掉。
  但 `updateAiCall` 這個「N 秒後在座標 P 放一個新對手進來」的排程器**整套留用**當進場管線。
  (逃跑演出本身很有戲——「老油條看你要贏了就開溜」列 §12 加分項。)

## 5. 魔法鑰匙(唯一的新玩法物件)

**掉落**:終演封存演出結束那一刻,回收艙吐出一把鑰匙(彈起 → 落在艙邊)。

**入袋——建議定案:自動飛入,不要手動撿。**
落地停留 ~0.8s 讓玩家看清楚,然後**自動飛向 HUD 的鑰匙計數器**。

- 理由:玩家的抱怨就是「東西太多、很亂」,再加一個「你必須走過去按 X」的必做步驟是逆向操作;
  漏撿還會生出一個新的卡關狀態。
- **飛行動畫是現成的**:flow-2b 的印章卡就是「生成 → 飛向計分格」(`v2s.recordCard`,`v2-hud.js:594`),
  換素材即可。
- 「掉落」的畫面感保留了(它真的掉出來、彈一下),只是不需要教一個新動作。

**顯示**:HUD 常駐 `🔑 1/3`。第 3 把入袋時整排鑰匙閃一次 + 大門亮起。
**資料**:`v2s.camp.keys`(0~3);`retry` 不清,`restartMatch`(整輪重來)才清。

## 6. 結局

3/3 → 場邊大門(或打卡機)亮起 + 一條指引 → 走過去 → **打卡下班演出**:
打卡機「嗶」→ 下班橫幅 → 走出大門。**不做總評報告、不做等級。**
結算畫面只留三件事:**通關時間**、**被回收次數**(`camp.deaths`,當笑點)、**重玩 / 回主選單**。

> ⚠ `inc.matchT`(`v2.js:215`)在報告退役後本來會變成死欄位——**留著當通關計時**。

## 14. 場景與主選單(2026-08-04 使用者提案)

> 使用者:「開頭應該加入主選單。主選單的背景就是玩家小人用第三人稱視角,不停在流水線上辛苦地工作;
> 開始遊戲的時候才會跑、準備逃跑下班。然後遇到 NPC 的開頭都會有一段台詞,叫玩家回去工作。」

### 14.1 為什麼這是對的

**它把「開場說明」變成「開場畫面」。** §8.1 原本打算用字卡講「18:47,今天第 11 個小時」;
選單版本直接**演給玩家看**:小人在流水線上機械地重複勞動,標題掛在上面,
**按下「開始」的那一刻=他決定不幹了**。玩家還沒按任何鍵就理解了全部動機——
這比任何教練行都更治 §1 的「亂」。選單畫面同時是 attract mode。

### 14.2 零件幾乎都是現成的

| 需要 | 現況 |
|---|---|
| 流水線 | `render-lab.js:729 conveyorBelt()`(滾筒+邊燈+移動包裹動畫)已存在,場上放了三條 |
| 工作動作 | 兩條路:①循環播現有 clip(`overhand` 當敲打工件);②**用現成搬運系統**讓小人撿瓶/桶走到定點放下再折返=「真的在工作」,零新動畫 |
| 第三人稱機位 | `CAM` 就是六個數字;加 `CAM_MENU` 預設,選單→遊戲的過渡**複用 intro 的 smoothstep 混合**(`v2.js:79-95`) |
| 選單 UI | DOM overlay 是既有慣例(報告的再戰/複製鈕、慢動作 pill) |

> ✅ **已查證(camp-0)**:`render-lab.js:1123` 那塊圍場造景是 `if (!RIMI)` 閘住的,rim 已退役 →
> **預設場上一條輸送帶都看不到**,而且那三條的座標本來就落在平台外的深淵上。
> 選單因此自己擺一條(`buildMenuStation`/`setMenuScene`/`MENU_STATION`),開打前整組隱藏。

### 14.3 附送的技術紅利:WebAudio 解鎖

瀏覽器規定 WebAudio 要等第一次使用者手勢才能出聲(`js/audio.js:3,16` 靠第一次輸入呼叫 `unlock()`)。
**「開始遊戲」的點擊就是那個手勢** → 從逃跑的第一幀起就有音效。現在的開場是啞的。

### 14.4 選單內容

極簡兩顆按鈕:**開始遊戲** / **加班模式**(未通關=鎖定灰字,通關後解鎖現有無限對戰)。
練習間(`training.html`)/道具間(`smokeroom.html`)是 repo 內部工具,**不上正式選單**。
標題見 §13 待拍板 #6。

### 14.5 NPC 進場台詞的呈現規則

台詞內容見 §8.3。**呈現方式有紀律**,否則會變成新的「亂」:

1. **不做凍結畫面的過場。** 第 2、3 關的 boss 在**走進場的路上**說台詞(氣泡/橫幅),
   玩家全程保有操作權——`updateAiCall` 本來就有 `CALL_T` 秒的走入時間,台詞掛這段上,節奏零損失。
2. **第 1 關例外**:從選單無縫接過來,可以給完整一拍——小人離開流水線走向大門 →
   老油條從出口走進來擋住 → 台詞 → 開打。**這段就是新的 intro**(取代現有字卡開場)。
3. **重打本關時台詞跳過或縮短**。聽過一次還重播就是懲罰。
4. **letterbox 電影感留給終演專用**(規格 G),台詞不搶。

### 14.6 敗北接回選單畫面(加分項,近乎零成本)

`retry(n)` 的「今天不用下班了」可以接回同一套工作循環:
**小人被丟回流水線繼續工作 1~2 秒 → 再次掙脫 → 重打本關**。
敗北懲罰本身變成笑點,而且與主選單共用同一段演出。
